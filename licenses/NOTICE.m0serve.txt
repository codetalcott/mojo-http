On macOS these are shipped as separate files beside the binary, which
resolves them through @loader_path:

    libKGENCompilerRTShared.dylib
    libMSupportGlobals.dylib
    libAsyncRTRuntimeGlobals.dylib

MODIFICATION NOTICE (Apache License 2.0, section 4(b)): each of these files
has been changed. Their Mach-O install name and rpath were rewritten so the
set resolves beside itself rather than in the directory it was built in, and
each was re-signed ad-hoc because arm64 macOS invalidates a code signature on
any Mach-O edit. No source was changed and no code was recompiled; the
executable code is byte-for-byte as Modular built it.

On Linux the same runtime is present as STATICALLY LINKED CODE inside the
m0serve binary rather than as separate files. There is no Modular file to
list, but the code is redistributed, and this notice covers it.

--------------------------------------------------------------------------------

CPython is NOT redistributed here.

m0serve resolves libpython at run time from the interpreter already installed
on the machine — it is not on the binary's link line and no CPython files are
included. That is also why the PyPI wheel carries no ABI tag: there is no
interpreter inside it to be compatible with, so one build serves every
supported CPython.

SQLite is not included either. The m0-sqlite bindings are a sibling package
that m0serve does not link.
